§ 规则示例

五份配置，以及每种规则类型的选用理由

每个示例都从一段对真实环境的自然描述开始，给出它对应的 JSON，再说明为什么选这种规则类型。你可以把任意一份直接粘进扩展，再按需修改。

多条规则同时命中时怎么裁决

一份配置里任意一条规则命中即生效。当多份配置的规则同时命中同一个页面时，分值最高的那条胜出。同类型规则之间，更长更具体的值分数更高 —— 所以精确域名永远压过宽泛的后缀匹配，你可以放心地让一条全公司默认规则和若干单域名覆盖规则共存。

类型匹配方式示例分值
host-exact域名与该值完全相同app.example.com1000 + 长度
ip-exact域名恰好是这个 IP192.0.2.5900
ip-cidr域名是该网段内的 IPv410.0.0.0/8800
url-regex完整 URL 匹配正则表达式^https?://.*/admin(/.*)?$700 + 长度
cookieCookie 名、精确值或包含deploy=canary650 / 600 / 550 + 长度
host-suffix该域名及其所有子域名example.com500 + 长度

Cookie 的三档分值对应三种写法：name=value 精确匹配值，name~=fragment 匹配包含关系，只写 name 则只判断是否存在。三者都会再加上 Cookie 名的长度。

五个示例

01

同域名多环境

我有三套环境共用同一个根域名：

  • https://app.example.com/ 是生产
  • https://test.app.example.com/ 是测试
  • https://staging.app.example.com/ 是预生产

我需要三种不同的水印，避免在错误的环境上误操作。

[
  {
    "name": "生产环境",
    "shortLabel": "PROD",
    "rules": [{ "type": "host-exact", "value": "app.example.com" }],
    "text": "生产环境 - 请谨慎操作",
    "color": "#ef4444",
    "opacity": 0.15,
    "border": { "enabled": true, "color": "#ef4444", "width": 4 }
  },
  {
    "name": "准生产",
    "shortLabel": "SIM",
    "rules": [{ "type": "host-exact", "value": "staging.app.example.com" }],
    "text": "准生产环境",
    "color": "#f59e0b",
    "opacity": 0.15
  },
  {
    "name": "测试环境",
    "shortLabel": "TEST",
    "rules": [{ "type": "host-exact", "value": "test.app.example.com" }],
    "text": "测试环境",
    "color": "#10b981",
    "opacity": 0.15
  }
]

选用理由：三个域名各不相同，所以 host-exact 是最精确的规则。生产用红色再加内嵌边框，这是最强的组合；预生产用琥珀色，测试用绿色。

02

VPN 内网管理后台（裸 IP）

我们的管理后台只能通过公司 VPN 访问 https://192.0.2.5/，没有域名，只有 IP。我想要一个紫色水印，写着「Admin — 受限区域」。

[
  {
    "name": "管理后台",
    "shortLabel": "ADMIN",
    "rules": [{ "type": "ip-exact", "value": "192.0.2.5" }],
    "text": "Admin — 受限区域\n仅授权人员访问",
    "color": "#8b5cf6",
    "opacity": 0.18,
    "border": { "enabled": true, "color": "#8b5cf6", "width": 3 }
  }
]

选用理由：浏览器里的 hostname 就是 192.0.2.5 本身，所以只能用 ip-exact —— 任何域名类规则在这里都不可能命中。边框打开，强化「受限」的感觉。

03

整个内网网段

内网 10.0.0.0/8 上的所有页面都应该带「INTERNAL」水印，外部网站不要。

[
  {
    "name": "内部网络",
    "shortLabel": "INT",
    "rules": [{ "type": "ip-cidr", "value": "10.0.0.0/8" }],
    "text": "INTERNAL NETWORK\n内部网络",
    "color": "#6366f1",
    "opacity": 0.12,
    "rotation": -25
  }
]

选用理由：10.0.0.0/8 是 A 类私有网段，约 1600 万个地址，一条规则全覆盖。它只在 hostname 是该范围内的裸 IPv4 时命中，而这正是纯内网工具的常态。

04

生产环境里按路径区分的管理页

生产站点 app.example.com 的主应用不用管，但我希望所有以 /admin 开头的 URL 都盖上大号红色 DANGER 水印，普通页面不要水印。

[
  {
    "name": "生产管理页",
    "shortLabel": "ADM",
    "rules": [
      { "type": "url-regex", "value": "^https://app\\.example\\.com/admin(/.*)?$" }
    ],
    "text": "DANGER — 生产管理页面\n此页可修改线上数据",
    "color": "#dc2626",
    "opacity": 0.2,
    "fontSize": 28,
    "border": { "enabled": true, "color": "#dc2626", "width": 5 }
  }
]

选用理由：这是按路径而非按域名区分，而 url-regex 是唯一会检查完整 URL 的类型。双反斜杠是 JSON 转义，用来表示正则里的字面点号；$ 是正则的结尾锚点。

05

靠 Cookie 区分的灰度环境

我们有一套灰度发布，URL 和生产完全一样（app.example.com），后端靠 deploy=canary 这个 Cookie 做路由。当我落在灰度上时，想要一个橙色的「CANARY」水印。

[
  {
    "name": "灰度环境",
    "shortLabel": "CNRY",
    "rules": [{ "type": "cookie", "value": "deploy=canary" }],
    "text": "CANARY 灰度环境",
    "color": "#f97316",
    "opacity": 0.15
  }
]

选用理由：同一个 URL、同一个域名，唯一的区分点就是 Cookie，任何域名或 URL 规则都帮不上。deploy=canary 匹配精确值；如果这个值会变，比如 canary-v1、canary-v2，改用 deploy~=canary 按包含关系匹配。

保存前先验一遍规则

设置页里有一个规则测试器。粘贴一个 URL，需要时再粘贴一段 Cookie 字符串，它会告诉你哪份配置会命中、以及是哪条规则命中的。这让上面每个示例都从「相信它能行」变成几秒钟就能验证。

URL 输入框
填你期望被标记的完整地址，例如 https://test.app.example.com/orders。域名、IP、网段和正则类规则都会拿它来求值。
Cookie 输入框
选填，按浏览器自己的写法填：deploy=canary; sid=abc。Cookie 规则必须靠它才能判定 —— 因为扩展是从页面里读 Cookie 的，而不是通过权限拿的。
危险正则拦截
过长或结构上会引发灾难性回溯的正则会被直接拒绝，不予执行，这样一个写坏的表达式不会把你访问的页面卡死。
